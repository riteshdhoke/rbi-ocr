1.0 Verdict
on v1 5 reversals

What survives the adversarial passसमीक्षा का सारांश

The v1 stage decomposition is sound and stays. The model matrix is mostly right. What v1 got wrong is not model selection — it is where the accuracy actually leaks, and it leaks in three places v1 barely mentions: scan quality, page-level language mixing, and an escalation router that cannot detect its own failures.

The single most important reframing: v1 spent its complexity budget on choosing between OCR models. In this domain, the dominant error source is not the recogniser. It is a phone photo of a form, taken at 15°, with a thumb over the account number.

assumption Untested
Riskजोखिम

The assumption that, if wrong, kills the design

Every other finding is survivable. This one is not: v1 assumes CPU-only inference can meet RBI-scale throughput, and offers no evidence for it. The figure "≥ 60 pages/min/node" appears as an exit criterion in Phase 3 — week 19 — which is the worst possible place to discover it is false. If it is false, the entire CPU-first premise collapses and the hardware budget, the deployment topology, and the phase plan all change.

Cheapest test — 1 day, week 1

Before writing any service code: take 100 representative pages, run PP-OCRv5_mobile INT8 under ONNX Runtime on the exact target instance type, with thread pinning applied, and measure p50/p95 wall-clock per page. Nothing else in Phase 0 starts until that number exists. It is a spike, not a milestone — one engineer, one day.

Standing control

4.0 Phase 0
architecture Added
Addedनया

Laptop-first: the provider splitचरण शून्य — बिना GPU विकास

The development machine has no GPU. The naive response is "put every model behind an API." That is wrong, and the reason matters:

The key insight

OCR is the part that works on a laptop. The SLM is the part that does not. PP-OCRv5_mobile INT8 is roughly 25 MB across detector, orientation and recogniser, and runs at 1–3 s/page on any modern laptop CPU. IndicTrans2-dist-200M under CTranslate2 INT8 is ~200 MB and also runs fine. It is only the 1.7B SLM and the 0.9B VLM that will not load. So route those two to the Hugging Face API, and keep everything else local — which also means Phase 0 is testing the real OCR code path, not a mock.

The compliance gate that must exist in code, not in a policy document

The HF API sends complaint text outside India. That is acceptable for synthetic data and unacceptable for anything else — under the DPDP Act and under any bank's data-residency clause. The control cannot be a wiki page.

# app/providers/factory.py
def get_provider(settings) -> ModelProvider:
    if settings.PROVIDER_PROFILE == "laptop" and not settings.SYNTHETIC_ONLY:
        raise ResidencyViolation(
            "laptop profile routes text to a non-Indian endpoint; "
            "it is permitted only with SYNTHETIC_ONLY=true"
        )
    return _REGISTRY[settings.PROVIDER_PROFILE](settings)

Pair it with a startup banner, a Prometheus gauge provider_profile{'{'}profile="laptop"{'}'} that alerts if it is ever non-zero outside a dev namespace, and a corpus loader that refuses any file lacking a synthetic: true sidecar.

Practical notes on the HF path

  • Use the OpenAI-compatible surface, not a bespoke client. Point an openai-SDK client at the HF router base URL with the HF token as the key. Swapping to a local llama.cpp server later is then a base-URL change, because llama.cpp also speaks OpenAI-compatible.
  • Free tier is a prototyping tier — a few hundred requests an hour, models under roughly 10B, cold starts on unpopular models. Pro at $9/month lifts the provider quota substantially. Budget for Pro from day one; the engineer's time is worth more than the tier difference.
  • Cache aggressively in dev. Key on sha256(model + prompt + params) to a local SQLite store. Iterating on downstream parsing shouldn't re-bill or re-wait on identical calls. This single decision makes Phase 0 iteration feel local.
  • Grammar constraints may not survive the API. Not every provider exposes GBNF or JSON-schema-constrained decoding. If the chosen provider does not, fall back to response_format JSON mode plus strict Pydantic validation with one repair retry — and record the schema-validity rate as a metric, because it is the number that will change when you move to local llama.cpp.
  • Contract tests run against every profile. Same 40 golden prompts, same assertions. A provider swap that changes behaviour must fail CI, not surprise you in Phase 2.
5.0 Revised
pipeline Stage 1.5 added
Supersededअधिक्रमित

Where the accuracy actually leaks

Two structural changes from v1. First, a quality gate before any model runs, with the authority to bounce a document back to the complainant rather than guess at it. Second, language identification moves to the line level, because the defining property of an RBI complaint is a printed English form with handwritten Marathi in the free-text box, and a single page-level language label silently corrupts everything downstream of it.

Finding A1 — the router cannot see its own failures

v1 escalates on mean line confidence. CTC confidence on Devanagari conjuncts is high and wrong: the model is confident about a plausible glyph sequence that is not the one on the page. A confidence-gated router therefore fails to escalate precisely the pages it exists to catch, and nothing in the system ever notices.

Fix

Escalate on evidence that is external to the model: a failed IFSC or Luhn check where the field was clearly present, a detected table or multi-column region, a handwriting flag from the detector, a script-classifier disagreement between lines, or a quality score below threshold. Then add the shadow sampler — route 3% of passed pages to Tier-2 anyway and diff the outputs. That percentage is the only honest estimate you will ever get of the router's false-negative rate, and it costs almost nothing.

Finding A3 — the summary is a liability

v1 has a sub-2B model write complaint_summary for a document that enters a regulatory adjudication. A generated sentence that subtly misstates the grievance is worse than no summary, and it is unattributable — there is no page or bbox to point at when someone asks where it came from.

Fix

Make the summary extractive. The SLM's job is to select spans, not compose prose: return line indices, and the assembler concatenates the verbatim OCR text of those lines. Every summary then carries bboxes and survives the "show me where this came from" question that an Ombudsman case officer will eventually ask.

6.0 Parallelism Specified
Addedनया

Four levels, and one rule that overrides all of them

v1 mentioned Celery concurrency and stopped there. Throughput on CPU is won at four distinct levels, and the largest single win is the one v1 omitted entirely: batching the recognition head.

The failure mode this prevents

ONNX Runtime, OpenVINO, llama.cpp and OpenBLAS each default independently to nproc threads. Celery prefork with concurrency 4 on an 8-core box therefore produces 32 threads contending for 8 cores, and the system runs 3–5× slower than a single-threaded version. Every profile must set OMP_NUM_THREADS before any numeric library is imported, and CI must assert the invariant concurrency × intra_op_threads ≤ physical_cores.

Async versus processes — do not mix them by accident

  • API profile (Phase 0): the NLP worker is I/O-bound. Use asyncio.gather over field groups inside a single process; concurrency 2–4 is plenty. Adding processes just multiplies your rate-limit exposure.
  • Local profile (Phases 1–3): the NLP worker is CPU-bound. Use prefork processes, one model instance each, no asyncio fan-out. A single Qwen3 instance saturates its threads; concurrent requests to it queue anyway.
  • The same code path must serve both. Put the fan-out behind provider.extract_batch(groups) and let the provider decide whether that means gather or a sequential loop.
7.0 Test data Reframed

Synthesise it, don't generate itपरीक्षण डेटा — संश्लेषण की रणनीति

The instinct is to ask an image model for "a scanned RBI complaint form, handwritten Marathi." Resist it, for three reasons that all point the same way:

  • No ground truth. A generated image has no label. You would then pay humans to transcribe your own synthetic data, which is the expense the synthetic data was supposed to avoid.
  • Indic script comes out as noise. Diffusion models render Devanagari as glyph-shaped nonsense. Training or evaluating a Devanagari recogniser on it is worse than useless — it is actively misleading.
  • Not reproducible. Regression testing needs the same corpus every run, versioned in git alongside the code.
The reframe

Render, then degrade. Compose each document from real text you control, using real Unicode fonts, then apply a physical-degradation pipeline — skew, blur, JPEG artefacts, shadow gradients, fold lines, staple holes, stamp overlays, thumb occlusion. Because you rendered it, you know every character's position: ground truth falls out for free. Ten document types × five variants × a degradation matrix gives you several hundred fully-labelled pages in an afternoon, against three to four weeks of human labelling.

The honest limit

Font-rendered handwriting with per-glyph jitter is not real handwriting. It validates the plumbing, the schema, the router and the throughput numbers. It does not validate handwriting accuracy. Any CER claim for handwritten Indic must be measured on real pages — IIIT's iiit-indic-hw-words for word-level, and a real complaint sample for page-level. Phase 1's exit criteria say so explicitly.

Full generator specification, degradation matrix, and the sidecar ground-truth format are in the separate test-data document.

Set aside, deliberately, for a later conversation

  • Complainant-facing pre-submission validator — the quality gate, moved upstream into the RBI CMS portal so the form is checked before it is ever emailed. Strictly better than anything downstream, and entirely outside this service's control. Worth raising with the RBI CMS team; not worth blocking on.
  • Cross-complaint linking — the same account number across multiple complaints is a signal about a bank, not just a complaint. Interesting, out of scope, and the schema's stable normalized field keeps the door open.
  • Bhashini integration — India's national language-services stack as a translation or OCR fallback. Government-operated, so it may satisfy residency where a commercial API cannot. Worth an evaluation spike in Phase 2.
